# Static SPMD on Ascend310P

A `@pl.jit` entry containing one static `pl.spmd(N)` grid, with `1 <= N <= 8`,
can execute as one CANN device task. Its kernel uses the physical coupled-core
identity. The entry and outlined kernel must use the same
FP16/FP32 tensors. A persisted permutation preserves the public argument order; dynamic orchestration and mixed-core groups are
outside this bridge. Compilation persists `a1_spmd.json`, including the required
block count. Artifact reload preserves this contract.

Use `A1L2Worker.prepare_spmd(compiled, *resident_tensors)` to bind a resident
grid. For two dependent grids, prepare their kernels with `worker.prepare()`
and register both calls, with their declared block counts, in one
`worker.register_graph()` sequence. Task completion orders their dependency.
`prepare_independent()` rejects these artifacts: virtualizing their grid to
one core would change `pl.spmd` semantics. Direct compiled calls support CPU
carriers with explicit upload and output download outside device execution.

DMA geometry stays static. Dynamic offsets must have provable nonnegative,
aligned bounds inside the complete source view. The current A1 bound is the
architectural eight-block grid; a smaller launch may still require a view
large enough for all eight possible indices. Positive-step bounded loops and
integer arithmetic are supported. Unknown scalar offsets, arithmetic overflow,
unaligned columns and out-of-bounds tiles remain rejected. No precision budget
or per-element arithmetic changes are implied by SPMD packing.

YOLO26 batch-eight exposes `spmd_attention_pack=True` as an opt-in. Each of
the two 400-position attention groups packs its ready Q/K/V routes and query
scaling into one public SPMD grid. Matrix consumers retain their original
order. FP32 scaling and CAST_NONE narrowing are preserved, and native routing
bit patterns remain the validation reference. The default stays disabled
until the paired full-model measurements establish a benefit.

Canonical ND `pl.tensor.view` aliases are also supported inside in-core
functions. A flat FP16/FP32 resident buffer can be viewed as a 2-D matrix
without allocating or copying; resident start offsets remain in force. DMA
still requires the existing aligned, bounded two-dimensional geometry.

YOLO26 uses public PyPTO for its persistent 400-column attention Softmax.
Each core loops over disjoint 16-row blocks; FP32 max/exp/sum/div operations
and CAST_NONE FP16 boundaries preserve the original row bit patterns. The
400-column path has no external C++ source. Batch-eight dispatch still binds
one independent image to each core and keeps one task per Softmax stage.
The compensated 16-column diagnostic path remains external.

The runtime pin selects an A1 vector implementation of packed row broadcast.
Supported FP16/FP32 shapes use transpose and bit-copy instructions without
scalar UB reads or additional UB allocation. Guarded shapes keep the scalar
fallback. The public Softmax lowering uses this implementation unchanged;
its arithmetic, task count and precision checks stay the same.
