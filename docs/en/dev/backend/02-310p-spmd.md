# Static SPMD on Ascend310P

A `@pl.jit` entry containing one static `pl.spmd(N)` grid, with `1 <= N <= 8`,
can execute as one CANN device task. Its kernel uses the physical coupled-core
identity. The entry and outlined kernel must use the same
FP16/FP32/INT32/UINT32 tensors. A persisted permutation preserves the public argument order; dynamic orchestration and mixed-core groups are
outside this bridge. Compilation persists `a1_spmd.json`, including the required
block count. Artifact reload preserves this contract. A single grid call may
return a tensor or be used only for its side effects.

Use `A1L2Worker.prepare_spmd(compiled, *resident_tensors)` to bind a resident
grid. For two dependent grids, prepare their kernels with `worker.prepare()`
and register both calls, with their declared block counts, in one
`worker.register_graph()` sequence. Task completion orders their dependency.
`prepare_independent()` rejects these artifacts: virtualizing their grid to
one core would change `pl.spmd` semantics. Direct compiled calls support CPU
carriers with explicit upload and output download outside device execution.

DMA geometry stays static. Dynamic offsets must have provable nonnegative,
aligned bounds inside the complete source view. The current A1 bound is the
architectural eight-block grid; a smaller launch may still require a view
large enough for all eight possible indices. Positive-step bounded loops and
integer arithmetic are supported. Unknown scalar offsets, arithmetic overflow,
unaligned columns and out-of-bounds tiles remain rejected. No precision budget
or per-element arithmetic changes are implied by SPMD packing.

YOLO26 batch-eight exposes `spmd_attention_pack=True` as an opt-in. Each of
the two 400-position attention groups packs its ready Q/K/V routes and query
scaling into one public SPMD grid. Matrix consumers retain their original
order. FP32 scaling and CAST_NONE narrowing are preserved, and native routing
bit patterns remain the validation reference. The default stays disabled
until the paired full-model measurements establish a benefit.

Canonical ND `pl.tensor.view` aliases are also supported inside in-core
functions. A flat FP16/FP32/INT32/UINT32 resident buffer can be viewed as a 2-D matrix
without allocating or copying; resident start offsets remain in force. DMA
still requires the existing aligned, bounded two-dimensional geometry.

YOLO26 uses public PyPTO for its persistent 400-column attention Softmax.
Each core loops over disjoint 16-row blocks; FP32 max/exp/sum/div operations
and CAST_NONE FP16 boundaries preserve the original row bit patterns. The
400-column path has no external C++ source. Batch-eight dispatch still binds
one independent image to each core and keeps one task per Softmax stage.
The compensated 16-column diagnostic path remains external.

The runtime pin selects an A1 vector implementation of packed row broadcast.
Supported FP16/FP32 shapes use transpose and bit-copy instructions without
scalar UB reads or additional UB allocation. Guarded shapes keep the scalar
fallback. The public Softmax lowering uses this implementation unchanged;
its arithmetic, task count and precision checks stay the same.

The existing `pl.load`/`pl.store` path also accepts INT32/UINT32 storage.
Integer tiles require full static row-major Vec geometry, 32-byte-aligned rows
and the existing UB budget; GM views retain bounded offsets and independent
strides. Allocation and ND `pl.tensor.view` use the same storage types. CPU
carriers and resident signatures preserve the integer dtype and four-byte ABI
elements. Integer arithmetic, casts, moves, tile subviews and matrix operands
remain outside this storage profile. Indexed gather is supported separately
as described below; sort instruction support remains a separate requirement.

The existing indexed `pl.gather(tile, index=indices)` and explicit
`pl.tile.gather(source, indices, scratch)` interfaces support FP16, FP32 and
INT32 values on A1, with INT32 flat element indices across the complete source
tile. Operands and result must be full static contiguous row-major Vec tiles
with 32-byte-aligned rows and bounded UB allocation. Partial, padded, strided
and nonzero-origin Tile views are rejected. GM views retain independent DMA
strides, aligned columns and resident Tensor start offsets. The source and
indices must be initialized, indices must lie inside the source, and writable
result/scratch storage must not alias other operands.

A1 uses one 32-bit byte offset per 16-bit value half: explicit INT32 scratch
requires at least the output element count for FP16, and twice that count for
FP32/INT32. High-level gather allocates this scratch automatically without
changing its existing result type. Full contiguous producers need no packing
copy or valid-shape mutation. The matching vectorized ISA consumes both source
and indices and writes byte-offset scratch on V; the compiler models those DMA
dependencies and the helper's scalar publication handshake. The implementation copies raw bits, preserving integer identities,
NaN payloads and signed zero.

The same public gather can be used in a static SPMD grid or `pl.pipeline` loop.
This profile does not support GM-source `tile.mgather`, axis/comparison
gather forms, and does not establish device performance. Model
defaults require separate device precision and paired performance acceptance.

## Fixed-block sorting

The existing `pl.sort32(values, indices)` and `pl.tile.sort32` support A1 FP32
values with matching UINT32 index tiles. Both inputs and the compact FP32
result require full static contiguous row-major Vec geometry; each source row
contains complete 32-value blocks. Each block returns 32 adjacent `[score,
index-bits]` pairs, ordered by descending score and ascending unsigned index
for equal scores. Input/index storage is read-only; signed zero and index
payload bits are preserved. NaN score ordering is not qualified.

A1 requires FP32 proposal scratch even for aligned input. With omitted `tmp`,
PyPTO/DSA-RP materialize two 32x8 banks per batched block before memory planning;
PTOAS's planner applies the same policy. Up to eight blocks share a batch
(`min(source_columns / 32, 8) * 512` FP32 elements), reused across rows. An
explicit `tmp` must contain at least 512 FP32 elements and satisfy the same
full-view/alignment and UB checks. Scratch/results must not overlap either
input or each other; the planner and native helper enforce writable separation.
The complete live allocation must fit the 128 KiB UB budget.

This path reuses the shared sort emitter and existing public operator; no model
C++ source is needed. Tests cover ordinary Tensor/Tile forms, explicit and
implicit workspace, memory planners, SPMD and two-stage pipeline loops, with
unmodified generated-code CPU oracles and dav-m200 offline compilation. Device
precision, asynchronous overlap and timing remain unqualified. This primitive
sorts independent 32-value blocks; a complete TopK also needs multi-list merge
and exact value/index extraction. Model defaults remain separately qualified.

## Multi-list merge and resident composition

The existing `pl.mrgsort` / `pl.tile.mrgsort` format2 merges two to four sorted
one-row FP32 `[score, index-bits]` lists on A1. Each source contains complete
16-pair groups (32 FP32 elements); full static row-major Vec geometry and the
128 KiB UB budget apply. Equal scores retain source-list priority and order
within that list. Payload bits are not reinterpreted or used as a tie breaker.

Supply explicit `output_cols` independently of scratch: a positive, 32-byte-aligned
prefix no wider than all input lists combined. For example, 600 elements retain
300 pairs. Scratch requires `8 * sum(source widths)` FP32 elements for two
native eight-field proposal banks. Sources are read-only; scratch and output
are disjoint from all live sources. Only `exhausted=False` is supported because
the public result has no consumed-count channel; format1 remains unsupported.

A block sort and several merge levels can stay inside one InCore kernel.
`pl.tile.reshape` and full-row `pl.tile.slice` expose adjacent sorted runs as
zero-copy aliases. All planners preserve their allocation and synchronization;
PTOAS planning requires the matching A1 reshape/row-subview support. No
intermediate GM load/store is needed. This composition is covered with 128/512
scores and 300/304-pair output prefixes, including unsigned payload ties,
multiple block counts and native offline compilation. Standalone merge also
covers SPMD and two-stage pipeline loops. Device precision and performance,
complete TopK extraction, and model defaults still need separate acceptance.

## Fixed-mask field extraction

The existing `pl.tile.gather_mask` supports A1 row-axis selection with all seven
`pl.tile.MaskPattern` patterns. FP16, FP32, INT32 and UINT32 inputs use full
static contiguous row-major Vec tiles. Source and selected rows must each be
32-byte aligned; the live allocation must fit the 128 KiB UB budget. Optional
`output_dtype` reinterprets same-width payload bits, without a numeric cast.
Input storage is read-only and output storage must not overlap it.

A1 lowers the existing mask form to VREDUCE, or a raw-bit identity copy for
P1111. No indices, scratch tile or intermediate GM copy is needed. The shared
emitter exposes static buffer aliases without changing allocation or valid
shape. Ordinary Tile, SPMD and two-stage pipeline forms use the existing
scheduling interfaces; the managed runtime ISA pin supplies the native helper.

A resident sort32-to-merge tree can extract scores with P0101 and UINT32 index
bits with P1010 before its final stores. The 512-score composition has two input
loads, two final stores and one generated kernel, with intermediate values in
UB. Extracting 300 independent FP32 fields would violate row DMA alignment;
304 fields provide an aligned intermediate. Consumers must retain exactly 300
logical detections through a separately verified trim. This support does not
change the model output contract or enable a complete TopK by itself.

CPU tests compare raw bits, input preservation and full output guards across
all mask patterns and storage types, including large vector-counter tails.
Generated dav-m200 code also compiles offline. Device launch counts, pipeline
overlap, strict model precision and paired performance still require device
acceptance before any model default changes.

## Scalar multiply and automatic pipeline buffers

The existing `tile.muls` emitter is enabled for FP16/FP32 A1 vector tiles;
Tile/Scalar `mul` canonicalization uses the same operation. No new IR operator
or arithmetic mode is introduced. This enables public attention conversion
that widens FP16 to FP32, multiplies by a metadata scalar, then optionally
narrows to FP16 with `mode="none"`.

`BackendHandler.supports_dynamic_pipeline_slots()` is false on A1 and true on
A2/A3/A5. `LowerPipelineToSlots` consults this capability through PassContext.
A1 automatic `pl.pipeline(stage=2)` retains replicated static double buffers
for PYPTO, PTOAS and DSA_RP planners. It does not emit an unsupported
`alloc_multi_tile` / `multi_tile_get` region; explicit dynamic slots remain
outside this A1 profile. Other targets retain their existing slot lowering.
Device overlap, latency and whole-model precision still require hardware
qualification before model defaults change.
