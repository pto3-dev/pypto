# Ascend310P 静态 SPMD

`@pl.jit` 入口中的单个静态 `pl.spmd(N)` grid（`1 <= N <= 8`）可作为一个
CANN 设备任务执行，kernel 使用耦合核的物理索引。入口与提取后的 kernel
必须使用相同的 FP16/FP32/INT32/UINT32 张量，保存的参数排列保持公共调用顺序。此桥接不支持动态编排与混合核组。
编译器通过 `a1_spmd.json` 保存所需 block 数，产物重载后仍保留该约束。
单个 grid 调用可返回张量，也可仅产生写入等副作用。

用 `A1L2Worker.prepare_spmd(compiled, *resident_tensors)` 绑定常驻 grid。
两个有依赖的 grid 可通过 `worker.prepare()` 准备，再把各自的声明 block 数
与参数交给同一个 `worker.register_graph()`，由任务完成顺序保证依赖。
`prepare_independent()` 会拒绝这些产物，避免把原语的 grid 错误虚拟化为单核。
直接调用编译产物也支持 CPU 张量，显式上传、输出下载位于设备执行区间之外。

DMA 几何保持静态，动态偏移必须能证明非负、对齐且完整 tile 位于源视图内。
当前 A1 使用架构的八 block 上界，所以较小 launch 的视图仍可能需要容纳八个
索引。支持正步长有界循环和整数算术；未知标量偏移、算术溢出、未对齐列偏移
及越界 tile 仍会被拒绝。SPMD 打包不改变逐元素运算与精度预算。

YOLO26 batch=8 提供显式选项 `spmd_attention_pack=True`，将两个 400 位置
attention 组各自已经就绪的 Q/K/V 复制与 query 缩放打包为一个公共 SPMD grid。
矩阵消费者保留原顺序，FP32 缩放与 CAST_NONE 窄化不变，以原生路由逐位结果
作为校验参考。同口径整模测量证明收益之前，默认保持关闭。

核内函数支持规范 ND 布局的 `pl.tensor.view` 别名 (alias)。平坦 FP16/FP32/INT32/UINT32
设备缓冲区可转换为二维矩阵视图，无需分配或复制；设备视图起始偏移仍然生效。
DMA 继续要求现有的对齐、边界可证明的二维几何约束。

YOLO26 的 400 列注意力 Softmax 使用公开 PyPTO 算子。每核循环处理互不重叠的
16 行块；FP32 max/exp/sum/div 和 CAST_NONE 的 FP16 边界保持原始行结果逐位一致。
400 列路径不再使用外部 C++ 源码。批量为 8 的 dispatch 仍为每核绑定独立图像，
每个 Softmax 阶段保持一个任务。16 列补偿精度的诊断路径仍使用外部实现。

runtime 固定版本选择了 A1 的向量行广播实现。支持的 FP16/FP32 形状使用转置和
位复制指令，不读取标量 UB，也不额外分配 UB。受形状限制的情况保留标量回退。
公开 Softmax 降低流程直接使用该实现，其运算顺序、任务数和精度检查保持不变。

既有 `pl.load`/`pl.store` 路径也支持 INT32/UINT32 存储 (storage)。
整数 tile 要求完整静态行主序 Vec 几何、32 字节行对齐及既有 UB 容量限制；
GM 视图保留有界偏移与独立步长。分配与 ND `pl.tensor.view` 复用相同存储类型。
CPU 载体与常驻参数签名保留整数 dtype 和四字节 ABI 元素。整数 arithmetic、cast、
move、tile 子视图与矩阵操作数仍不在该存储 profile 内。索引 gather 的支持范围
见下文；排序指令仍需独立支持。

既有索引式 `pl.gather(tile, index=indices)` 与显式
`pl.tile.gather(source, indices, scratch)` 接口在 A1 支持 FP16、FP32 和
INT32 值；INT32 索引是整个源 Tile 展平后的元素偏移。操作数与结果必须是完整、
静态、连续行主序 Vec Tile，行按 32 字节对齐且分配满足 UB 容量。拒绝部分有效
形状、补齐跨度、非连续和非零起点的 Tile 视图。GM 视图保留独立 DMA 跨度、
对齐的列偏移及常驻 Tensor 起点偏移。源与索引必须初始化，索引必须位于源范围
内，结果与 scratch 等可写存储不能与其他操作数重叠。

A1 的每个 16 位值半字需要一个 32 位字节偏移：显式 INT32 scratch 对 FP16
至少容纳结果元素个数，对 FP32/INT32 至少容纳其两倍。高层 gather 自动分配
该 scratch，不改变既有结果类型。完整连续的生产者无需额外打包复制或修改有效
形状。匹配的向量化 ISA 在 V 上读取源与索引、写偏移 scratch；编译器建模这些 DMA
依赖及 helper 的最终标量 publication 握手。实现复制原始位，保留整数身份、NaN payload 与符号零。

同一公共 gather 可用于静态 SPMD 网格和 `pl.pipeline` 循环。本支持范围不含
GM 源 `tile.mgather`、按轴/比较式 gather，也不代表已验证设备性能。
模型默认路径仍需独立设备精度与同口径性能验收。

## 固定块排序

既有 `pl.sort32(values, indices)` 和 `pl.tile.sort32` 支持 A1 FP32 数值与同形状
UINT32 索引。输入及紧凑 FP32 结果要求完整静态、连续行主序 Vec，每行包含完整
32-value 块。每块输出32个相邻 `[score, index-bits]` pair，分数降序，相同分数按
无符号索引升序；输入/索引只读，保留有符号零和索引载荷位。尚未验证NaN分数排序。

即使输入对齐，A1也需要FP32 proposal scratch。省略 `tmp` 时，PyPTO/DSA-RP在内存
规划前生成两组32x8 proposal bank；PTOAS规划器采用相同策略。每批最多八块，容量为
`min(source_columns / 32, 8) * 512` 个FP32元素，跨行复用。显式 `tmp` 至少512个
FP32元素，满足相同的完整视图、对齐与UB检查。Scratch/结果不得与输入或彼此重叠，
规划器和原生helper检查可写范围分离；全部活跃分配必须适合128 KiB UB。

路径复用公共算子及共享emitter，不需要模型C++源。测试覆盖Tensor/Tile、显式/隐式
工作区、内存规划器、SPMD、两阶段pipeline，使用未经手改的生成代码CPU oracle与
dav-m200离线编译。设备精度、异步重叠和时延尚未验证。该原语仅独立排序32-value块，
完整TopK仍需多列表归并及精确的值/索引提取；模型默认路径另行验收。

## 多列表归并与片上串联

既有 `pl.mrgsort` / `pl.tile.mrgsort` format2 在A1归并2–4个已排序的单行FP32
`[score, index-bits]` 列表。每个源包含完整16-pair组（32个FP32元素），并满足完整
静态行主序Vec几何与128 KiB UB预算。分数相同时保留源列表优先级及列表内顺序；
载荷位不做数值转换，也不作为相等分数的次级排序键。

须显式提供独立于scratch的 `output_cols`：正数、32字节对齐，且不超过全部源的
总宽度。例如600个元素保留300对。Scratch至少包含 `8 * sum(source widths)` 个
FP32元素，用于两组原生八字段proposal bank。源只读；scratch和输出不得与活跃源
重叠。公共结果没有消耗计数通道，故仅支持 `exhausted=False`；format1仍不支持。

块排序与多级归并可保留在一个InCore kernel中。`pl.tile.reshape` 和完整行
`pl.tile.slice` 将相邻有序段暴露为零拷贝别名。各规划器保留共享分配及同步；PTOAS
规划需配套A1 reshape/整行子视图支持，无需中间GM搬运。串联测试覆盖128/512个分数、
300/304-pair输出前缀、无符号载荷平分、多种核数和原生离线编译。独立归并另覆盖
SPMD与两阶段pipeline。设备精度及性能、完整TopK提取、模型默认路径仍需分别验收。

## 固定 mask 字段提取

既有 `pl.tile.gather_mask` 在 A1 上支持行轴选择和全部七种
`pl.tile.MaskPattern`。FP16、FP32、INT32 和 UINT32 输入使用静态完整、连续、
行主序 Vec tile；源行和选取后的行均须满足 32 字节对齐，存活分配不得超过
128 KiB UB。可选 `output_dtype` 对相同位宽的载荷做位重解释，不做数值转换。
源存储只读，输出不得与源重叠。

A1 使用 VREDUCE；P1111 使用原始位复制。无需索引、scratch 或中间 GM 拷贝。
共用 emitter 生成静态 buffer 别名，不改变分配或有效形状。普通 Tile、SPMD
和双阶段 pipeline 复用既有调度接口；原生 helper 通过 runtime 的托管 ISA pin
获取。

驻留的 sort32→merge 树可用 P0101 提取分数、P1010 提取 UINT32 索引位，再做
最终写回。512 分数的组合仅有两次输入 load、两次最终 store 和一个生成 kernel，
中间值保留在 UB。300 个独立 FP32 字段不满足行 DMA 对齐；304 字段可作为对齐
中间段，但消费者必须通过另行验证的截断保留恰好 300 个逻辑检测结果。
本支持不改变模型输出合同，也不代表完整 TopK 已完成。

CPU 测试覆盖所有 mask 和存储类型，逐位比较、检查输入只读及完整输出 guard，
并覆盖大向量计数器尾部；生成的 dav-m200 代码通过离线编译。设备 launch 数量、
pipeline 重叠、严格整模精度与配对性能仍须设备验收，之后才能改变模型默认路径。

## 标量乘法与自动 pipeline 缓冲

A1 的 FP16/FP32 向量 Tile 已启用既有 `tile.muls` emitter；Tile/Scalar 的
`mul` 规范化也复用该算子，不新增 IR 算子或算术模式。公共注意力转换由此可将
FP16 扩展为 FP32、乘以 metadata 标量，再按需用 `mode="none"` 缩窄为 FP16。

`BackendHandler.supports_dynamic_pipeline_slots()` 在 A1 为 false，在
A2/A3/A5 为 true。`LowerPipelineToSlots` 通过 PassContext 查询该能力。
A1 的自动 `pl.pipeline(stage=2)` 在 PYPTO、PTOAS、DSA_RP 三种规划器下
均保留展开后的静态双缓冲，不生成尚不支持的 `alloc_multi_tile` /
`multi_tile_get` region；显式动态 slot 仍不在 A1 支持范围内。其他目标保持
原 slot lowering。设备重叠、时延与整模精度仍需真机验收后才能改变模型默认路径。
